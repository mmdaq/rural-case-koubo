# ============================================================
# 农村集体资产案例口播文案机器人（rural-case-koubo）
# ============================================================
# 一个每天早晨 8 点自动运行的机器人：
#   1. 只采集"人民法院案例库 + 最高人民法院发布的典型案例"中的真实案例
#   2. 核查案例真伪（官方可查锚点：官方链接 / 入库编号+裁判文书号 / 多源交叉，三选一）
#   3. 查重去重（持久化去重库，同一案例不重复推送）
#   4. 按【用户痛点 + 案件细分类型】生成 5 篇"真实案例改编"的纯口播文案
#      （每个案例的入库编号/官方链接单独一行写在标题前，结尾附留言引导）
#   5. 发送到你的邮箱（默认 QQ 邮箱 SMTP）
#
# 文案风格示例（与内置种子案例一致）：
#   入库编号：2024-07-2-044-005
#   官方链接：http://dyzy.sdcourt.gov.cn/.../2025041809054199852.pdf（有则显示）
#   标题：离婚回村，村里说股权证没你名就没钱拿
#   正文：海南高院再审改判的案例……集体的钱就有你一份。
#   评论区互动：你们村有没有类似"离婚就不给分钱"的规矩？评论区说出来，我帮你看看合不合法。
# ============================================================

├── scheduler.py           # 常驻定时调度（schedule 库）

## 写作规则（v2）

1. **案例参考来源限定**：只使用 ① 人民法院案例库（rmfyalk.court.gov.cn）入库案例；② 最高人民法院发布的典型案例（court.gov.cn）。其余网络转载仅作交叉核实用，不作为唯一来源。
2. **真实可查**：每个案例必须满足"官方可查锚点"之一才能推送：
   - 官方链接（案例库/最高法官网/政府法院系统官网域名）；
   - 入库编号 + 裁判文书号（两者均可在官方渠道检索核实）；
   - 入库编号 + ≥2 个独立域名转载来源。
   不满足锚点或内容残缺的案例一律丢弃，绝不放行"带病"案例。
3. **痛点 + 细分类型写作**：正文按案例对应用户痛点（信息不对称 / 民主决策虚置 / 问题合同泛滥 / 证据取证难 / 群体性矛盾 / 报复压制 / 执行难）与案件细分类型定向撰写，先戳痛点、再讲案情、结尾点法律态度。
4. **纯口播文案**：只输出 标题 + 正文 + 评论区互动（留言引导）。案例核查信息以"入库编号/官方链接"行呈现在标题前，不混入分析、说明类内容。
5. **判决结果不杜撰**：涉及金额、判决内容一律以案例记录中的 `result`（判决结果）字段为准，模板与 LLM 均禁止自行推断。

## 官网在线核对（推荐开启）

除锚点校验外，推送前会**逐案到人民法院案例库官网（rmfyalk.court.gov.cn）按入库编号检索核对**：

- 官网查得到 → 该案文案自动带上官网详情链接（可点击核实）；
- 官网查不到 → 该案例直接拦截、不推送（防止编号抄错或杜撰）；
- Token 失效或官网不可达 → 自动降级为"锚点校验"继续发送，并在日志中告警
  （`verify.online.require: false`，保证每天不中断；Token 有效时仍逐案强制核对、查不到即拦截）。

启用方法：浏览器登录案例库官网 → F12 → 网络面板 → 发起一次检索，
复制请求头 `faxin-cpws-al-token` 的值，在仓库 Settings → Secrets and variables → Actions
新建 secret：`RMFYALK_TOKEN`（粘贴该 Token）。Token 过期后重新获取更新即可。

> Token 会不定期失效，属正常现象：失效当天日志会提示"官网在线核对不可用，降级为锚点校验"，
> 文案仍会照常发送；有空时重新登录官网取新 Token 更新 Secret，即可恢复逐案在线核对。

## 自我扩充机制（每日自动探索新案例）

案例池 = **内置种子（8个人工核实） + 扩展案例库（自动发现累积）**，每日运行按三层探索：

1. **预置转载链接池**：内置人工核实的案例库原文页与"一网一库"专题页（支持一页多案例提取，澎湃专题一页含5个完整案例）；
2. **转载源列表翻页**：税递网"人民法院案例库"栏目等持续翻页（该栏目全部为案例库内容，不再按标题预过滤，扩大案例池）；
3. **搜索引擎检索**：辅助源（受网络环境影响，失败自动跳过）。

探索到的页面经 `extractor.py` 提取结构化字段（入库编号/案名/案情/裁判理由/裁判要旨/判决结果/省份/金额/主题标签）→ **主题过滤**（只保留农村集体资产相关）→ **真伪校验（官方可查锚点必检）** → 写入 `data/extra_cases.json` 扩展库。

**已抓 URL 记录**（`data/crawled_urls.json`，随仓库提交）：每次运行只抓取"没抓过"的新页面，税递网案例库栏目最多翻 60 页、每源抓取上限 150 个详情页，配合搜索引擎辅助源，案例池随每日运行持续累积、越滚越大。

**每日5篇的选材逻辑（轮换制）**：
1. **未推送过的新案例优先**；
2. 其次选择**超过冷却期（默认7天）**的案例，按"最久没发过"优先；
3. 再次选择冷却期内但非最近推送的案例；
4. 案例池不足时才复用最近推送的案例。

因此只要案例池充足，**同一案例不会连续两天重复出现**；即使案例池较小，也会从最久未推送的案例轮换，避免连续两天发出同一批文案。扩展库随运行持续累积，案例池越滚越大。

## 快速开始

### 1. 安装依赖

```bash
cd rural-case-koubo
pip install -r requirements.txt
```

### 2. 配置

复制配置模板并填写：

```bash
cp .env.example .env
```

`.env` 中必填两项（敏感信息不入库、不提交 Git）：

```ini
# QQ 邮箱 SMTP 授权码（不是登录密码！）
# 获取：QQ邮箱 → 设置 → 账户 → 开启 SMTP 服务 → 生成授权码
MAIL_SENDER=你的邮箱@qq.com
MAIL_AUTH_CODE=你的16位授权码
MAIL_RECEIVERS=385096659@qq.com

# 可选：LLM API Key（不填则用本地模板引擎生成文案，效果稍弱）
LLM_API_KEY=sk-xxx
```

> 收件人也可直接写在 `config.yaml` 的 `mail.receivers` 中；`MAIL_RECEIVERS` 支持多个邮箱，用英文逗号分隔。

### 3. 试运行

```bash
# 立即执行一次，生成文案到 data/output/ 但不发邮件
python main.py dry-run

# 确认无误后，立即执行一次完整流程（会真正发邮件）
python main.py run-once
```

### 4. 定时：每天早晨 8 点

**方式 A：常驻进程（简单）**

```bash
python main.py daemon        # 默认每天 08:00 执行，可用 nohup 或 systemd 守护
```

**方式 B：系统 crontab（推荐，省资源）**

```bash
crontab -e
# 加入：
0 8 * * * cd /path/to/rural-case-koubo && /usr/bin/python3 main.py run-once >> data/logs/cron.log 2>&1
```

**方式 C：Docker**

```bash
docker build -t rural-case-koubo .
docker run -d --name rck -v $(pwd)/data:/app/data --env-file .env rural-case-koubo
```

### 方式 D：GitHub Actions 云端自动运行（推荐，电脑不用开机）

项目内置 `.github/workflows/daily-run.yml`，推送后由 GitHub 服务器每天自动执行，**无需自己的电脑/服务器在线**。

**① 推送后配置 Secrets（必须，否则邮件发不出去）**

仓库页面 → **Settings** → 左侧 **Secrets and variables** → **Actions** → **New repository secret**，逐个添加：

| Secret 名称 | 值 | 必填 |
|---|---|---|
| `MAIL_SENDER` | 你的QQ邮箱，如 385096659@qq.com | ✅ |
| `MAIL_AUTH_CODE` | QQ邮箱SMTP授权码（16位） | ✅ |
| `MAIL_RECEIVERS` | 收件邮箱，多个用英文逗号分隔 | ✅ |
| `LLM_API_KEY` | DeepSeek API Key（提升文案质量） | 可选 |
| `RMFYALK_TOKEN` | 人民法院案例库官网登录 Token（开启逐案官网核对，推荐） | 可选(推荐) |

**② 手动测试一次**

仓库 **Actions** 页面 → 左侧选"每日农村案例口播推送" → 右侧 **Run workflow** → 绿色按钮。约 2-5 分钟后运行成功，检查邮箱是否收到5篇文案。

**③ 之后每天自动跑**

工作流内置定时 `0 0 * * *`（UTC）= **每天北京时间 08:00** 自动执行：采集探索 → 核查去重 → 生成5篇 → 发邮件。

**④ 每日不重复的保障**

- `data/seen_cases.json`（去重库）与 `data/extra_cases.json`（扩展案例库）**随仓库提交持久化**（已配置好，不要删它们或加入 .gitignore）；
- 每次运行结束后，工作流自动把这两个文件 `git commit + push` 回仓库，因此云端每次运行都是"接着上次继续"，不会重复推送同一案例。

**⑤ 查看/下载每天文案**

Actions 运行页 → 该次运行的 **Artifacts** 区可下载当天的 `口播文案-日期.md`。

> 免费额度：公共仓库 Actions 无限时长；私有仓库每月 2000 分钟，本项目每天约 3-5 分钟，绰绰有余。

## 案例真伪核查机制

每个案例推送前经过严格校验（`utils/validator.py`，默认 `strict: true`，不满足即丢弃）：

1. **入库编号格式**：正则校验 `YYYY-XX-X-XXX-XXX`（如 `2024-07-2-044-005`），与人民法院案例库编号规则一致；
2. **内容要素**：正文必须包含"人民法院/判决/征收/补偿/集体经济组织/成员资格"等关键词，防无关内容混入；
3. **官方可查锚点（必检）**：官方链接（rmfyalk.court.gov.cn / court.gov.cn / *.gov.cn）或 入库编号+裁判文书号 或 入库编号+≥2 个独立域名来源；
4. **判决结果字段**：金额与判决内容以 `result` 字段为准，避免生成环节臆造。

手工核查单个案例文件：

```bash
python main.py verify --file my_case.json
```

## 查重去重机制

- 去重库持久化在 `data/seen_cases.json`，**以入库编号为唯一键**（同一案例即使标题表述不同也只算一次，防止同案不同标题绕过去重）；
- **轮换选材**（`pipeline._select_candidates`）：未推送案例 → 超过冷却期的最早推送案例 → 冷却期内但非最近的案例 → 最近推送兜底；
- 冷却期与最小间隔可在 `config.yaml` 的 `generator` 下配置（`cooldown_days: 7`、`min_gap_days: 1`）；
- 只要案例池充足，同一案例不会连续两天重复出现；案例池不足时从最久未推送的案例开始轮换，不会连续两天发出同一批案例。

## 常见问题

**Q：不填 LLM_API_KEY 能跑吗？**
能。自动降级为内置模板引擎（`generator/template.py`），按主题句式库生成，风格接近示例但灵活度略低。建议填写 DeepSeek Key 获得最佳效果（`LLM_BASE_URL`、`LLM_MODEL` 可切换任意 OpenAI 兼容服务）。

**Q：人民法院案例库官网抓不到数据？**
官网 `rmfyalk.court.gov.cn` 需登录，多数服务器环境不可达，属正常现象。项目设计为：官网→最高院→搜索引擎→内置种子 逐级降级，任何情况下每日任务都能产出 5 篇基于真实案例的文案。你也可以把人工核实的案例 JSON 追加进 `fallback.py` 的 `SEED_CASES`，扩大案例池。

**Q：如何扩充案例池？**
新案例必须包含：`rule_code`（入库编号）、`title`、`facts`、`reasoning`、`gist`、`source_urls`，并满足"官方可查锚点"（官方链接 或 入库编号+裁判文书号 或 ≥2 个独立来源）。建议同时提供 `result`（判决结果）、`official_link`（官方可查链接）、`subtype`（细分类型）、`pain_points`（痛点）。可先用 `python main.py verify --file x.json` 自检格式。

**Q：文案里的金额/判决结果会不会被 AI 编出来？**
不会。模板引擎与 LLM 提示词都规定：金额、判决内容一律以案例记录中的 `result`（判决结果）字段为准；没有该字段时只做泛化表述，不推断具体数字。每个案例的入库编号/官方链接都会在标题前单独成行，可到人民法院案例库逐案核实。
