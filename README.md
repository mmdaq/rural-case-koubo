# ============================================================
# 一个每天早晨 8 点自动运行的机器人：
#   1. 搜集人民法院案例库 / 最高人民法院官网 与农村、集体资产相关的真实案例
#   2. 核查案例真伪（入库编号格式校验 + 字段完整性 + 多源交叉验证）
#   3. 查重去重（持久化去重库，同一案例不重复推送）
#   4. 生成 5 篇"真实案例改编"的口播文案（LLM 生成，本地模板兜底）
#   5. 发送到你的邮箱（默认 QQ 邮箱 SMTP）
#
# 文案风格示例（与内置种子案例一致）：
#   入库编号：2024-07-2-044-005
#   标题：离婚回村，村里说股权证没你名就没钱拿
#   正文：海南高院2024年再审改判的案例……集体的钱就有你一份。
#   评论区互动：你们村有没有类似"离婚就不给分钱"的规矩？……

## 自我扩充机制（每日自动探索新案例）

案例池 = **内置种子（8个人工核实） + 扩展案例库（自动发现累积）**，每日运行按三层探索：

1. **预置转载链接池**：内置人工核实的案例库原文页与"一网一库"专题页（支持一页多案例提取，澎湃专题一页含5个完整案例）；
2. **转载源列表翻页**：税递网"人民法院案例库"栏目等持续翻页（标题预过滤涉农关键词，只抓相关详情页）；
3. **搜索引擎检索**：辅助源（受网络环境影响，失败自动跳过）。

探索到的页面经 `extractor.py` 提取结构化字段（入库编号/案名/案情/裁判理由/裁判要旨/省份/金额/主题标签）→ **主题过滤**（只保留农村集体资产相关）→ **真伪校验** → 写入 `data/extra_cases.json` 扩展库。

**每日5篇的选材逻辑**：去重库保证"同一案例不重复推送"，**未推送过的新案例优先**；当日无新案例时从扩展库+种子轮换补足，**保证每天5篇照常发出，不会停发**。扩展库随运行持续累积，案例池越滚越大。

## 快速开始

### 1. 安装依赖

```bash
cd rural-case-koubo
pip install -r requirements.txt
```

### 2. 配置

复制配置模板并填写：

```bash
cp .env.example .env
```

`.env` 中必填两项（敏感信息不入库、不提交 Git）：

```ini
# QQ 邮箱 SMTP 授权码（不是登录密码！）
# 获取：QQ邮箱 → 设置 → 账户 → 开启 SMTP 服务 → 生成授权码
MAIL_SENDER=你的邮箱@qq.com
MAIL_AUTH_CODE=你的16位授权码
MAIL_RECEIVERS=385096659@qq.com

# 可选：LLM API Key（不填则用本地模板引擎生成文案，效果稍弱）
LLM_API_KEY=sk-xxx
```

> 收件人也可直接写在 `config.yaml` 的 `mail.receivers` 中；`MAIL_RECEIVERS` 支持多个邮箱，用英文逗号分隔。

### 3. 试运行

```bash
# 立即执行一次，生成文案到 data/output/ 但不发邮件
python main.py dry-run

# 确认无误后，立即执行一次完整流程（会真正发邮件）
python main.py run-once
```

### 4. 定时：每天早晨 8 点

**方式 A：常驻进程（简单）**

```bash
python main.py daemon        # 默认每天 08:00 执行，可用 nohup 或 systemd 守护
```

**方式 B：系统 crontab（推荐，省资源）**

```bash
crontab -e
# 加入：
0 8 * * * cd /path/to/rural-case-koubo && /usr/bin/python3 main.py run-once >> data/logs/cron.log 2>&1
```

**方式 C：Docker**

```bash
docker build -t rural-case-koubo .
docker run -d --name rck -v $(pwd)/data:/app/data --env-file .env rural-case-koubo
```

## 案例真伪核查机制

每个案例推送前经过三重校验（`utils/validator.py`）：

1. **入库编号格式**：正则校验 `YYYY-XX-X-XXX-XXX`（如 `2024-07-2-044-005`），与人民法院案例库编号规则一致；
2. **内容要素**：正文必须包含"人民法院/判决/征收/补偿/集体经济组织/成员资格"等关键词，防无关内容混入；
3. **多源交叉验证**：同一案例出现在 ≥2 个独立域名来源才算高可信（`min_independent_sources` 可调）。

手工核查单个案例文件：

```bash
python main.py verify --file my_case.json
```

## 查重去重机制

- 去重库持久化在 `data/seen_cases.json`；
- 以 **入库编号 + 标题归一化哈希** 为键，同一案例不重复推送；
- 若某日采集结果全部为已推送案例，自动回退使用内置种子案例，保证每日有产出。

## 常见问题

**Q：不填 LLM_API_KEY 能跑吗？**
能。自动降级为内置模板引擎（`generator/template.py`），按主题句式库生成，风格接近示例但灵活度略低。建议填写 DeepSeek Key 获得最佳效果（`LLM_BASE_URL`、`LLM_MODEL` 可切换任意 OpenAI 兼容服务）。

**Q：人民法院案例库官网抓不到数据？**
官网 `rmfyalk.court.gov.cn` 需登录，多数服务器环境不可达，属正常现象。项目设计为：官网→最高院→搜索引擎→内置种子 逐级降级，任何情况下每日任务都能产出 5 篇基于真实案例的文案。你也可以把人工核实的案例 JSON 追加进 `fallback.py` 的 `SEED_CASES`，扩大案例池。

**Q：如何扩充案例池？**
新案例必须包含：`rule_code`（入库编号）、`title`、`facts`、`reasoning`、`gist`、`source_urls`。可先用 `python main.py verify --file x.json` 自检格式。
